
`زبان برنامه نویسی جاوا`

`یک زبان شی‌گرا و چندمنظوره است که شباهت‌های زیادی به زبان‌های C و ++C دارد. در اصلی، جاوا از زبان C الهام گرفته و سعی کرده برخی از مشکلات آن را برطرف کند. از سوی دیگر، این زبان سادگی را به عنوان یکی از ویژگی‌های اصلی خود حفظ کرده که باعث محبوبیت بالای آن نزد توسعه دهندگان شده است. با استفاده از جاوا، امکان پیاده‌سازی تقریبا هر نوع برنامه‌ای وجود دارد؛ از توسعه برنامه‌های اندروید گرفته تا توسعه نرم افزار، توسعه هوش مصنوعی، علوم داده، طراحی بازی و حتی توسعه برنامه‌های وب!`

`تاریخچه زبان Java`

`توسط شرکت Sun Microsystems در دهه ۱۹۹۰ میلادی توسعه داده شد. شرکت سان میکروسیستمز در حال کار روی زبان برنامه نویسی جدیدی بود که بتواند مشکلات رایج C در اجرا در پلتفرم‌های مختلف و مشکلات دیگری که مربوط به مدیریت حافظه بودند را حل کند. جیمز گاسلینگ، مامور انجام این کار شد و توانست زبان برنامه نویسی فوق العاده‌ای را طراحی کند که علاوه بر برطرف کردن ضعف‌های گفته شده، ویژگی‌های مثبت زیادی را به عنوان یک زبان برنامه نویسی ارائه کرد. علاوه بر این، زبان جاوا به عنوان یک زبان شی‌گرا شناخته می‌شود و مفاهیم شی‌گرایی یا OOP به خوبی در آن پیاده‌سازی شده است.`

`این زبان برای اولین بار در سال ۱۹۹۵ منتشر شد و به سرعت، نزد توسعه‌دهندگان مختلف به محبوبیت رسید. شرکت اوراکل (Oracle) کمی بعد از محبوبیت بالای جاوا، امتیاز آن را خریداری کرد و مدیریت وساده‌تر نسبت به C و  ++`C

`یکی از دلایل مهم برای توسعه زبانی دیگر به جای استفاده از C، این بود که کدهای آن دارای پیچیدگی‌های زیادی بودند. در صورتی که کدهای یک زبان دارای پیچیدگی زیادی باشد، مدیریت و نگهداری کدها کار بسیار سختی خواهد بود. جاوا با حذف بسیاری از ویژگی‌های اضافی ++C و C و کمی هم ساده‌سازی سینتکس، توانست محبوبیت چشمگیری را در زمان انتشار کسب کند. توسعه آن را برعهده گرفت.`

`نسخه‌های مختلف جاوا`

`شرکت سان مایکروسیستمز، کیت توسعه نرم‌افزاری (JDK) شماره 1.0 جاوا را در سال 1995 منتشر کرده است. این JDK نخست برای توسعه اپلیکیشن‌های دسکتاپ و اَپلت (applet) مورد استفاده قرار گرفت. متعاقباً جاوا برنامه‌نویسی دستگاه‌های موبایل و سرورهای تجاری را نیز در این کیت میسر ساخت. ذخیره‌سازی همه کتابخانه‌ها در یک JDK منفرد باعث شده که این کیت بسیار بزرگ‌تر از حد مناسب برای توزیع شود. البته باید این نکته را در نظر داشته باشید که توزیع نرم‌افزارها در دهه 1990 توسط CD های اندازه کوچک و یا از طریق سرعت‌های پایین شبکه صورت می‌گرفته است. از آنجا که اغلب توسعه‌دهندگان به همه API ها نیاز نداشتند (یک توسعه‌دهنده اپلیکیشن‌های دسکتاپ به ندرت به API های سرورهای تجاری نیاز پیدا می‌کند) شرکت Sun این مشکل توزیع را با تقسیم جاوا به سه نسخه حل کرد. این نسخه‌ها نهایتاً به نام JAVA SE، JAVA EE و JAVA ME نامیده شدند که در ادامه هر کدام را توضیح داده‌ایم.`

### Naming Conventions

در Java، «اصول نام‌گذاری» یا `naming  conventions` مجموعه‌ای از قواعد رایج برای خواناتر و استانداردتر نوشتن کد هستند. این‌ها اجباریِ زبان نیستند، ولی تقریبا همه از آن‌ها پیروی می‌کنند.

**قواعد اصلی**

- نام `class` ها با `PascalCase`
    - حرف اول هر کلمه بزرگ است



```java
class StudentRecord
class BankAccount
```

- نام `method` ها با `camelCase`
    - کلمه اول با حرف کوچک، کلمات بعدی با حرف بزرگ



```java
calculateTotal()
getName() 
printReport()
```

- نام `variable` ها با `camelCase`



```java
int studentAge;
double finalPrice;
String firstName;
```

- نام `constant` ها با `UPPER_CASE`
    - معمولا برای `static final`



```java
static final double PI = 3.14159;
static final int MAX_USERS = 100;
```

- نام `package` ها با حروف کوچک



```java
com.myapp.util java.lang org.example.project
```

**برای interface**

- معمولا مثل کلاس با `PascalCase`



```java
interface Printable interface Runnable
```

**برای enum**

- نام `enum` مثل کلاس با `PascalCase`
- مقادیر داخل آن معمولا `UPPER_CASE`
- مقادیر داخل آن اگر از یک واژه بیشتر بود با آندرلاین یا **underscore (`_`)** جدا کنید



```java
	enum Day { MONDAY, TUESDAY, WEDNESDAY }
	enum OrderStatus {
    PENDING_PAYMENT,
    IN_PROGRESS,
    DELIVERED_ON_TIME,
    CANCELED_BY_USER
}

```

**برای فایل**

- نام فایل باید با نام `public class` یکی باشد



```java
public class Student { }
```

اسم فایل:



```java
Student.java
```

**چند نکته مهم**

- اسم‌ها باید معنی‌دار باشند
    - خوب:



```java
int totalMarks;
String customerName;
```

- بد:


```java
int x;
String a;
```

- از اسم‌های خیلی کوتاه و مبهم پرهیز کن، مگر در موارد ساده مثل حلقه‌ها



```java
for (int i = 0; i < 10; i++) { }
````

- نام متد بهتر است فعل‌محور باشد(امری باشد)



```java
saveData() calculateSalary() sendEmail()
```

- نام متغیر و کلاس بهتر است هدف را مشخص کند



```java
Employee employee;
List<String> studentNames;
```

```java

 public class StudentManager {  
    static final int MAX_STUDENTS = 500;   
       private String schoolName;  
          private int totalStudents;

   }
 }

# 1-فایل `.class` چیست؟

وقتی شما یک کد جاوا (با پسوند .java) می‌نویسید و آن را کامپایل می‌کنید، کامپایلر جاوا (javac) آن را به کدهای میانی به نام بایت‌کد (Bytecode) تبدیل می‌کند. این بایت‌کدها در فایلی با پسوند .class ذخیره می‌شوند.
هر کلاس (یا اینترفیس) در جاوا، پس از کامپایل به یک فایل .class مجزا تبدیل می‌شود.
اگر پروژه شما ۱۰۰ کلاس داشته باشد، شما ۱۰۰ فایل .class خواهید داشت.

# 4-چرا قبلا میگفتن جاوا نسخه 1.8 ولی الان میگویند ورژن 1.21 نمی گویند 21؟

علت این تغییر به **تغییر سیاست نام‌گذاری (Versioning Scheme)** توسط شرکت Sun Microsystems و بعداً Oracle برمی‌گردد.

یک داستان تاریخی و بازاریابی پشت این قضیه است:

### ۱. دوران نام‌گذاری با پیشوند `.1` (تا جاوا ۸)

در ابتدا که جاوا معرفی شد، نسخه‌ها با شماره‌های واقعی خود نام‌گذاری می‌شدند:

- Java 1.0 (سال ۱۹۹۶)
- Java 1.1 (سال ۱۹۹۷)

در سال ۱۹۹۸، زمانی که نسخه **1.2** منتشر شد، تغییرات بسیار بزرگی در جاوا رخ داد (مثل معرفی Swing و Collections). تیم بازاریابی تصمیم گرفت برای اینکه نشان دهد جاوا وارد فاز بسیار بزرگی شده است، نام تجاری آن را به **Java 2** تغییر دهد، اما در پشت صحنه و کدهای سیستمی، نام نسخه همچنان **1.2** بود.

این روند تا سال‌ها ادامه داشت:

- نام تجاری: **Java 5** ─── نسخه سیستمی: **1.5**
- نام تجاری: **Java 8** ─── نسخه سیستمی: **1.8**

توسعه‌دهندگان قدیمی به دلیل خروجی دستوراتی مثل `java -version` که مقدار `1.8.x` را نشان می‌داد، عادت کرده بودند به آن بگویند **جاوا ۱.۸**.

### ۲. تغییر بزرگ در نسخه ۹ (یکدست‌سازی نام‌گذاری)

از نسخه ۹ به بعد، اوراکل تصمیم گرفت این سردرگمی دوگانه (نام تجاری متفاوت با نسخه سیستمی) را حل کند. آن‌ها پیشوند کلیشه‌ای `1.` را به طور کامل حذف کردند:

- به جای **1.9**، نسخه رسماً و سیستماتیک **9** نامیده شد.
- خروجی `java -version` نیز به جای `1.9.0` مقدار `9.0.x` را نشان داد.

این روند برای نسخه‌های بعدی یعنی ۱۰، ۱۱، ۱۷ و در نهایت **۲۱** نیز ادامه پیدا کرد.

# 5-تغییرات اساسی در نسخه های جاوا در کدام نسخه ها بود ؟


جاوا در طول سال‌ها تغییرات زیادی داشته، اما چند نسخه به عنوان **«نقاط عطف» (Milestones)** شناخته می‌شوند که پارادایم‌ها و ساختار زبان را به کل تغییر دادند.

در اینجا مهم‌ترین نسخه‌ها و تغییرات اساسی آن‌ها آورده شده است:

### ۱. Java 5 (یک جهش بزرگ در نحو زبان)

این نسخه جاوا را از یک زبان ساده به یک زبان مدرن‌تر تبدیل کرد.

- **Generics:** اضافه شدن نوع‌های عمومی (مثل `List<String>`) برای جلوگیری از خطاهای زمان اجرا.
- **Annotations:** اضافه شدن آنوتیشن‌ها (مثل `@Override`).
- **Enum:** اضافه شدن نوع داده شمارشی.
- **Autoboxing/Unboxing:** تبدیل خودکار بین انواع Primitive (مثل `int`) و کلاس‌های Wrapper (مثل `Integer`).
- **Enhanced for-loop:** معرفی حلقه `for-each`.

### ۲. Java 8 (تغییر پارادایم به سمت برنامه‌نویسی تابعی)

شاید **مهم‌ترین نسخه تاریخ جاوا** باشد که سبک کدنویسی را کاملاً عوض کرد.

- **Lambda Expressions:** امکان نوشتن کدهای مختصر به سبک Functional.
- **Stream API:** روشی جدید و قدرتمند برای پردازش مجموعه‌ها (Collections).
- **Optional Class:** راهکاری برای مقابله با خطای معروف `NullPointerException`.
- **Default Methods:** اجازه تعریف بدنه متد در اینترفیس‌ها.
- **Date & Time API:** معرفی پکیج جدید و استاندارد `java.time`.

### ۳. Java 9 (تغییر در معماری سیستم)

- **Module System (Project Jigsaw):** جاوا به قطعات کوچک‌تری به نام ماژول تقسیم شد. این کار باعث شد حجم برنامه‌ها (به خصوص در محیط‌های ابری) کمتر شود و امنیت بالاتر برود.
- **jshell:** اضافه شدن محیط REPL برای تست سریع کدهای جاوا بدون نیاز به ساخت کلاس.

### ۴. Java 11 (نسخه LTS و تغییرات زیرساختی)

- **حذف JRE جداگانه:** از این نسخه به بعد نصب JRE مستقل منسوخ شد و فقط JDK ارائه شد.
- **HttpClient جدید:** جایگزین شدن کتابخانه قدیمی با یک API مدرن که از HTTP/2 و WebSocket پشتیبانی می‌کند.
- **متغیر var:** استفاده از `var` برای متغیرهای محلی (که در نسخه ۱۰ معرفی شده بود در ۱۱ تثبیت شد).

### ۵. Java 17 (نسخه LTS بعدی و بهبودهای نحوی)

- **Sealed Classes:** کنترل دقیق بر اینکه کدام کلاس‌ها می‌توانند از یک کلاس دیگر ارث‌بری کنند.
- **Records:** کلاس‌های بسیار مختصر برای نگهداری دیتا (جایگزین کدهای تکراری Getter/Setter).
- **Pattern Matching for switch:** (به صورت پیش‌نمایش) قدرت بخشیدن به دستور switch.

- **Structured Concurrency:** ساده‌سازی مدیریت کارهای موازی.

## primitive data type in java ?

در Java، `primitive data type` یعنی «نوع داده‌ی اولیه/ساده»؛ داده‌هایی که به‌صورت مستقیم مقدار را نگه می‌دارند و `object` نیستند.

انواع primitive در Java این 8 مورد هستند:

- `byte` : عدد صحیح کوچک
- `short` : عدد صحیح کوتاه
- `int` : عدد صحیح معمولی
- `long` : عدد صحیح بزرگ
- `float` : عدد اعشاری
- `double` : عدد اعشاری دقیق‌تر
- `char` : یک کاراکتر
- `boolean` : مقدار منطقی `true` یا `false`

مثال:
```java
int age = 25;
double price = 19.99;
char grade = 'A';
boolean isJavaFun = true
```


تفاوت مهم:

- `primitive` ها ساده و سریع‌تر هستند
- مقدار واقعی را مستقیم نگه می‌دارند
- متد ندارند
- با `wrapper class` ها فرق دارند، مثلا:
    - `int` ← `Integer`
    - `double` ← `Double`

```java
int a = 10;
int b = a;
b = 20;

System.out.println(a); // 10
System.out.println(b); // 20
```
اینجا `b` یک کپی از مقدار `a` را می‌گیرد.

پس تغییر `b` روی `a` اثری ندارد.

**متد (Method)** که در برخی زبان‌های برنامه‌نویسی به آن **تابع (Function)** نیز گفته می‌شود، بلوکی از کدهاست که وظیفه انجام یک کار مشخص را بر عهده دارد و تنها زمانی اجرا می‌شود که آن را صدا بزنید (فراخوانی کنید).
### چرا از متدها استفاده می‌کنیم؟

- **جلوگیری از تکرار کد (DRY - Don’t Repeat Yourself):** به جای اینکه یک تکه کد را در چند جای پروژه کپی کنید، آن را یک‌بار درون یک متد می‌نویسید و هر جا نیاز بود فراخوانی می‌کنید.
- **خوانایی بیشتر برنامه:** تقسیم برنامه‌های بزرگ به بخش‌های کوچک‌تر و قابل فهم‌تر.
- **نگهداری آسان‌تر:** اگر تغییری در منطق کد نیاز باشد، فقط کافی است بدنه متد را ویرایش کنید، نه کل پروژه.
### ساختار کلی (Syntax) تعریف یک متد در جاوا

یک متد معمولاً به شکل زیر تعریف می‌شود:



```java
modifier returnType methodName(parameterList) { 
// بدنه متد (کدهایی که باید اجرا شوند)   
return value; // (اختیاری: اگر متد خروجی داشته باشد) 

}
```


### اجزای تشکیل‌دهنده یک متد

هر متد از چند بخش اصلی تشکیل شده است:

1. **سطح دسترسی یا اصلاح‌گر (Modifier):** مشخص می‌کند چه کسانی به این متد دسترسی دارند (مانند `public` یا `private` یا `static`).
2. **نوع بازگشتی (Return Type):** مشخص می‌کند متد بعد از انجام کارش، چه نوع داده‌ای را به ما پس می‌دهد (مثلاً `int`، `String` یا اگر هیچ خروجی نداشته باشد `void`).
3. **نام متد (Method Name):** نامی که برای متد انتخاب می‌کنیم تا با آن صدا زده شود (در جاوا معمولاً به سبک camelCase نوشته می‌شود، مثل `calculateSalary`).
4. **لیست پارامترها (Parameters List):** ورودی‌های متد که داخل پرانتز تعریف می‌شوند (می‌تواند خالی هم باشد).
5. **بدنه متد (Method Body):** کدهایی که بین دو آکولاد `{ }` قرار می‌گیرند و کار اصلی متد را انجام می‌دهند.


### مثال‌

#### ۱. متد بدون ورودی و بدون خروجی (`void`)

این متد کار ساده‌ای انجام می‌دهد و هیچ مقداری را به بیرون پس نمی‌دهد:



```java
// تعریف متد 
public void sayHello() { 
System.out.println("سلام! به برنامه خوش آمدید.");
}
// نحوه فراخوانی: sayHello();
```
#### ۲. متد با ورودی و بدون خروجی

این متد ورودی (پارامتر) می‌گیرد اما خروجی ندارد:



```java

public void greetUser(String name) { 
    System.out.println("سلام " + name); } 
     // نحوه فراخوانی (Ali یک آرگومان است): 
     greetUser("علی");
```

#### ۳. متد با ورودی و با خروجی

این متد ورودی‌ها را می‌گیرد، پردازش می‌کند و نتیجه را با دستور `return` پس می‌فرستد:



```java
// تعریف متد
 public int sum(int a, int b) { 
     int result = a + b;  
        return result; // بازگرداندن نتیجه

تفاوت بین **پارامتر (Parameter)** و **آرگومان (Argument)** بسیار ساده اما کلیدی است. این تفاوت در زمان **تعریف** متد در مقابل زمان **فراخوانی (اجرا)** متد مشخص می‌شود:

### ۱. پارامتر (Parameter) چیست؟

پارامترها همان **متغیرهایی** هستند که در **تعریف متد** (امضای متد) نوشته می‌شوند. آن‌ها مانند جایگاه‌های خالی (Placeholder) عمل می‌کنند که مشخص می‌کنند این متد برای اجرا شدن به چه نوع داده‌هایی نیاز دارد.

- **زمان:** زمان کدنویسی و تعریف متد (Compile-time).
- **مکان:** در پرانتز جلوی نام متد هنگام تعریف آن.

**مثال:**

```java
// در اینجا a و b پارامتر هستند
 public int add(int a, int b) {  
     return a + b; 
     }
```


### ۲. آرگومان (Argument) چیست؟

آرگومان‌ها همان **مقادیر واقعی** هستند که شما در زمان **فراخوانی متد** به آن پاس می‌دهید تا متد با استفاده از آن‌ها اجرا شود.

- **زمان:** زمان اجرای برنامه (Runtime).
- **مکان:** در پرانتز جلوی نام متد هنگام صدا زدن آن.

**مثال:**



```java
// در اینجا 5 و 10 آرگومان هستند 
int result = add(5, 10);
```

## سازنده (Constructor) در جاوا چیست؟

**سازنده** متدی ویژه است که هنگام ساختن شیء (با `new`) به‌صورت خودکار اجرا می‌شود و معمولاً برای **مقداردهی اولیه (initialize)** فیلدها و آماده‌سازی وضعیت شیء استفاده می‌شود.


## ویژگی‌های اصلی سازنده

- **نامش دقیقاً نام کلاس است.**
- **نوع بازگشتی ندارد** (حتی `void` هم ندارد).
- می‌تواند **پارامتر** بگیرد (سازنده پارامتردار) یا نگیرد (پیش‌فرض/بدون پارامتر).
- می‌تواند **Overload** شود (چند سازنده با امضای متفاوت).
- می‌تواند از داخل خودش به سازنده دیگر همان کلاس زنجیر شود با `this(...)`.
- در وراثت، سازنده کلاس فرزند باید اول سازنده کلاس پدر را صدا بزند با `super(...)` (یا ضمنی انجام می‌شود).



## 1) سازنده پیش‌فرض (Default Constructor)

اگر شما **هیچ سازنده‌ای تعریف نکنید**، کامپایلر جاوا یک سازنده بدون پارامتر به صورت خودکار ایجاد می‌کند:


```java
class Person {   
String name; 
}
```

معادل ضمنی:



```java
class Person { 
    String name;
          Person() {  
                 super(); // ضمنی    
                  }
                   }
```

اما اگر **حتی یک سازنده** (مثلاً پارامتردار) تعریف کنید، دیگر سازنده پیش‌فرض به صورت خودکار ساخته نمی‌شود.

## access modifiers

 در Java، `access modifiers` مشخص می‌کنند که یک `class`، `variable`، `method` یا `constructor` از کجا قابل دسترسی باشد.

4 نوع اصلی داریم:

- `public`
- `protected`
- `default` (بدون نوشتن modifier)
- `private`

**توضیح هرکدام**

- `public`
    - از همه جا قابل دسترسی است.

```java
public class Test {
    public int x = 10;
}
```


- `private`
    - فقط داخل همان کلاس قابل دسترسی است.

```java
class Test {
    private int x = 10;
}
```



- `protected`
    - داخل همان پکیج و همچنین در `subclass` ها قابل دسترسی است.

```
protected int age;
```


- `default`
    - وقتی چیزی ننویسی، عضو فقط داخل همان `package` قابل دسترسی است.

```java
class Test {
    int x = 5;   // default
}
```

مثال:
```java
class Person {
    public String name;
    private int age;
    protected String city;
    String job; // default
}
```
در این مثال:

- `name` از همه جا قابل دسترسی است
- `age` فقط داخل کلاس `Person`
- `city` داخل پکیج و subclass
- `job` فقط داخل همان پکیج

### نکات مربوط به استاتیک static


کلمه کلیدی **`static`** در جاوا به زبان ساده یعنی: **«متعلق به خودِ کلاس است، نه نمونه‌ها (اشیاء) ساخته شده از روی آن کلاس»**.
وقتی چیزی را در جاوا با کلمه کلیدی `static` تعریف می‌کنید (متغیر، متد، بلوک کد یا کلاس داخلی)، به این معنی است که برای استفاده از آن نیازی به ساختن شیء با دستور `new` ندارید و آن عضو بین تمام نمونه‌های کلاس **مشترک** است.

در جاوا، **خودِ متغیر استاتیک (رابط یا رفرنس آن) و مقداری که به آن ارجاع می‌دهد، هر دو در حافظه هیپ (Heap) قرار می‌گیرند و به هیچ وجه در استک (Stack) ذخیره نمی‌شوند.**

### متغیر استاتیک (Static Variable) - متغیر کلاس
اگر یک متغیر را `static` تعریف کنید، فقط **یک نسخه** از آن متغیر در حافظه ایجاد می‌شود که بین تمام اشیاء آن کلاس مشترک است.
 **بدون استاتیک:** هر شیء کپی مخصوص به خود را از متغیر دارد.
**با استاتیک:** همه اشیاء به یک متغیر واحد اشاره می‌کنند.

### متد استاتیک (Static Method)
متدهایی هستند که متعلق به کلاس هستند و بدون ساختن شیء از کلاس، مستقیماً با نام کلاس صدا زده می‌شوند.
متدهای استاتیک **فقط** می‌توانند متغیرها و متدهای استاتیک دیگر را مستقیماً صدا بزنند.
متدهای استاتیک نمی‌توانند از کلمه کلیدی `this` یا `super` استفاده کنند (چون شیء‌ای وجود ندارد که `this` به آن اشاره کند).
### بلوک استاتیک (Static Block)

برای مقداردهی اولیه به متغیرهای استاتیک استفاده می‌شود. این بلوک **فقط یک‌بار**، آن هم زمانی که کلاس برای اولین بار در حافظه بارگذاری (Load) می‌شود، اجرا می‌شود (حتی قبل از متد `main` یا سازنده کلاس).

```java
class Test { 
static int number; 
static { 
number = 50;
 System.out.println("Static block executed!"); 
}
 }
```
### ۱. متغیرهای استاتیک کجا ذخیره می‌شوند؟

از نسخه جاوا ۸ به بعد، متغیرهای استاتیک (Static Variables) در بخشی از حافظه هیپ به نام **`Metaspace`** (بخش مربوط به اطلاعات کلاس‌ها یا Class Metadata) ذخیره می‌شوند.

- _در نسخه‌های قدیمی‌تر جاوا (جاوا ۷ و قبل از آن)، این متغیرها در بخشی از هیپ به نام Permanent Generation یا همان `PermGen` ذخیره می‌شدند که آن هم بخشی از حافظه اصلی سیستم/هیپ بود._

### ۲. چرا استاتیک‌ها در استک (Stack) قرار نمی‌گیرند؟

حافظه **Stack** برای ذخیره «فریم‌های متد» (Method Frames) است. یعنی:

- **متغیرهای محلی** (Local Variables) که درون یک متد تعریف می‌شوند.
- پارامترهای ورودی متدها.
- اطلاعات مربوط به ترتیب صدا زدن متدها (Call Stack).

وقتی اجرای یک متد تمام می‌شود، فریم مربوط به آن متد از روی استک حذف (Pop) می‌شود و تمام متغیرهای محلی آن از بین می‌روند. از آنجا که متغیرهای استاتیک متعلق به کل کلاس هستند و طول عمری برابر با طول عمر برنامه (یا دقیق‌تر، کلاس‌لودر) دارند، نمی‌توانند در استک قرار بگیرند؛ چون باید مستقل از اجرای متدها در دسترس بمانند.

مثال 
```java
public static int connectionLimit = 10; // متغیر استاتیک (نوع پرایمتیو) 
public static String dbUrl = new String("jdbc:mysql://localhost:3306/db");
```

`نکته ی بسیار مهم : غیراستاتیک در استاتیک به صورت مستقیم نمیتوان استفاده کرد` برای مثال متغیر کلاس که غیر استاتیک تعریف شده است را با ایجاد شی از روی آن کلاس میتوان در متد استاتیک استفاده کرد. 

در جاوا نمی‌توان کلاس‌های بیرونی (Outer Classes) را به صورت static تعریف کرد چرا؟
چون `static` در جاوا فقط برای عضوی معنا دارد که **وابسته به یک enclosing type** باشد؛ یعنی عضوی که قرار است بگوییم «این عضو به خود کلاس تعلق دارد، نه به شیء».
اما **کلاس بیرونی خودش already top-level است** و چیزی بالاتر از آن نیست که `static` نسبت به آن معنا پیدا کند.

### main method

در Java، `main method` نقطه شروع اجرای برنامه است.

یعنی وقتی برنامه Java اجرا می‌شود، JVM اول دنبال متد `main` می‌گردد.

## شکل استاندارد main



```java
public static void main(String[] args) { 
System.out.println("Hello World");
 }
```

## معنی هر بخش

### `public`

یعنی این متد از بیرون کلاس هم قابل دسترسی است تا JVM بتواند آن را اجرا کند.

### `static`

یعنی بدون ساختن object از کلاس هم می‌شود این متد را اجرا کرد.

### `void`

یعنی این متد چیزی برنمی‌گرداند.

### `main`

اسم خاصی است که JVM برای شروع برنامه می‌شناسد.

### `String[] args`

برای گرفتن آرگومان‌های خط فرمان استفاده می‌شود.
## مثال ساده



```java
public class Test {    
 public static void main(String[] args) {  
        System.out.println("Program started");   
  }
   }
```

## مثال با آرگومان

اگر برنامه را با ورودی اجرا کنیم:



`java Test Ali 25`

کد:



```java
public class Test {
public static void main(String[] args) {
        System.out.println(args[0]); // Ali   
              System.out.println(args[1]); // 25    
               } 
               }
```

## چرا static است؟

چون قبل از اینکه objectی از کلاس ساخته شود، JVM باید بتواند برنامه را شروع کند.

پس `main` باید `static` باشد.

## نکته

این هم معتبر است:


```java
public static void main(String args[]) { }
```

چون:


`String[] args`

و


`String args[]`

هر دو درست هستند.

### String class


کلاس `String` در Java برای نگهداری و کار با متن استفاده می‌شود.

مثال:



```java
String name = "Ali";
```

اینجا `name` یک شیء از کلاس `String` است.

**ویژگی مهم `String`**

- `String` یک `reference type` است
- برای ذخیره متن استفاده می‌شود
- `immutable` است؛ یعنی بعد از ساخته شدن، مقدارش عوض نمی‌شود
![[7.png]]

مثال:



```java
String s = "Hello";
 s = s + " World";
 System.out.println(s);
```

در ظاهر انگار `s` تغییر کرده، اما در واقع یک `String` جدید ساخته شده است.

**چند متد پرکاربرد `String`**

- `length()` : طول رشته



```java
String text = "Java";
 System.out.println(text.length()); // 4
```

- `charAt(index)` : گرفتن کاراکتر در یک اندیس



```java
String text = "Java";
 System.out.println(text.charAt(1)); // a
```

- `toUpperCase()` : تبدیل به حروف بزرگ



```java
String text = "java"; 
System.out.println(text.toUpperCase()); // JAVA
```

- `toLowerCase()` : تبدیل به حروف کوچک



```java
String text = "JAVA";
 System.out.println(text.toLowerCase()); // java
```

- `equals()` : مقایسه محتوای دو رشته



```java
String name = "Ali"; 
String otherName = "Ali";
 System.out.println(a.equals(otherName)); // true
```

- `contains()` : بررسی وجود یک متن داخل رشته



```java
String test = "I love Java";
 System.out.println(test.contains("Java")); // true
```

- `substring()` : بریدن بخشی از رشته



```java
String text = "Programming";
 System.out.println(text.substring(0, 7)); // Program
```

**تفاوت `==` و `equals()` در String**

- `==` مرجع را مقایسه می‌کند
- `equals()` محتوا را مقایسه می‌کند

مثال:



```java
String a = new String("Java");
 String b = new String("Java");
   System.out.println(a == b);// false
        System.out.println(a.equals(b)); // true
```

**ساختن String**

دو روش رایج:



```java
String s1 = "Hello";
String s2 = new String("Hello");
```

روش اول رایج‌تر و بهتر است.


# آرایه (Array) در جاوا

آرایه یک ساختار داده است که تعداد ثابتی از عناصر **هم‌نوع** رو در حافظه پیوسته نگه می‌داره.


## تعریف و مقداردهی


``` java
// روش ۱: تعریف + مقداردهی جدا 
int[] numbers = new int[5];
 numbers[0] = 10;
   // روش ۲: مقداردهی مستقیم
    int[] numbers = {10, 20, 30, 40, 50}; 
     // روش ۳: new با مقادیر 
     int[] numbers = new int[]{10, 20, 30}; 
      //   syntax برای تعریف  
       int[] arr1;
    
```

---

## دسترسی و ویژگی‌ها



```java
int[] arr = {10, 20, 30};  
arr.length;      // 3 (نه متد، یک field است) arr[0];          // 10 arr[arr.length - 1];  // آخرین عنصر = 30  // ایندکس از 0 شروع می‌شه // arr[3] → ArrayIndexOutOfBoundsException
```



## پیمایش (Loop)



```java
int[] arr = {1, 2, 3, 4, 5}; 
// for معمولی
 for (int i = 0; i < arr.length; i++) {     System.out.println(arr[i]); } 
  // for-each 
 for (int num : arr) {     System.out.println(num); }
```



## آرایه چند بعدی



``` java

   for (int[] row : grid) {  
      for (int val : row) {  
             System.out.print(val + " ");   
               } 
               }

## نکات مهم

### ۱. آرایه‌ها Fixed-size هستن



```java
int[] arr = new int[5];
// arr.length همیشه 5 باقی می‌مونه، نمی‌شه resize کرد // برای resize باید آرایه جدید بسازی و کپی کنی، یا از ArrayList استفاده کنی
```

### ۲. آرایه‌ها Reference type هستن



```java
int[] a = {1, 2, 3};
 int[] b = a;        // b و a به همون آرایه اشاره می‌کنن
b[0] = 100; 
System.out.println(a[0]);  // 100 (چون reference یکسانه)
```

### ۳. مقدار پیش‌فرض


```java 
int[] arr = new int[3];      // {0, 0, 0}
boolean[] flags = new boolean[3]; // {false, false, false}
String[] strs = new String[3];    // {null, null, null}
```

## 4. حذف مقدار از آرایه 

چون آرایه معمولی قابلیت کوچک شدن ندارد، باید یک آرایه جدید با یک خانه کمتر بسازید و بقیه مقادیر را به آن کپی کنید.

### مقداردهی به Null (اگر فقط می‌خواهید داده حذف شود)

اگر فقط می‌خواهید داده‌ی داخل یک خانه خالی شود (مثلاً برای آزاد کردن حافظه یک آبجکت) و طول آرایه مهم نیست، آن را `null` کنید:



```java
String[] names = {"Ali", "Reza", "Hasan"};
 names[1] = null;   // آرایه همچنان طولش ۳ است، اما ایندکس ۱ خالی شده است`
